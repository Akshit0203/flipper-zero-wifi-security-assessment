# Contributing

Thanks for your interest in this project. It is a **documentation-focused educational write-up** of a wireless security assessment, so contributions are mostly about improving clarity, accuracy, and defensive value.

## Ground Rules

1. **Ethics first.** Contributions must preserve the educational and defensive intent of this repository. Pull requests that add operational guidance for attacking networks without authorization, remove the disclaimer, or otherwise encourage illegal use will be rejected.
2. **Accuracy.** Technical corrections (protocol details, command syntax, tool versions) are very welcome — please cite a source where relevant.
3. **No sensitive data.** Never commit real capture files (`.pcap`, `.cap`), hash files (`.22000`, `.hccapx`), wordlists, recovered keys, MAC addresses of third-party networks, or personal information.

## How to Contribute

1. Fork the repository.
2. Create a feature branch: `git checkout -b improve-docs`.
3. Make your changes (see areas below).
4. Commit with a clear message.
5. Open a pull request describing **what** changed and **why**.

## Good Areas to Contribute

- Fixing typos, broken links, or formatting.
- Clarifying a step in the `docs/` walkthrough.
- Updating tool/firmware versions as they change.
- Expanding the **defensive** guidance in `docs/05-defense-and-mitigations.md`.
- Improving diagrams or adding clearer annotated screenshots (from your own equipment only).

## Reporting Issues

Open a GitHub issue for errors, outdated steps, or suggestions. Please do **not** open issues requesting help attacking networks you do not own — such requests will be closed.
